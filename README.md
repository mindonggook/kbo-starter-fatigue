# 선발이 내려오는 순간

KBO 10시즌(2017–2026)으로 본 선발투수 피로도와 교체 타이밍.

> **선발이 내려오는 이유는 피로가 아니다.** 피로는 실재하지만 결과를 크게 움직이지 않고,
> 결과를 움직이는 것은 타자가 그 투수의 구종을 배워가는 과정이다.

리포트(발견 40개 + 부록): **[여기에 아티팩트 링크를 넣는다]**

---

## 1. 무엇을 했나

KBO에는 Statcast도, 공개 API도, 내려받을 수 있는 경기 파일도 없다.
웹페이지에서 직접 만들어 낸 데이터로 분석했다.

| 데이터셋 | 행 | 단위 |
|---|---:|---|
| 투수 등판 기록 | 66,499 | 등판 1건 |
| 타석 상태 (점수·아웃·주자) | 559,276 | 타석 1건 |
| 투구 단위 | 2,076,805 | 투구 1개 |
| 타석 득점가치 (RE24) | 493,597 | 타석 1건 |
| 타석 승리확률 (WPA) | 480,667 | 타석 1건 |
| 네이버 추적 (구속·구종·좌표) | 186,945 | 투구 1개 |

원본 캐시 7,772개 / 164.6MB, 코드 56파일 / 약 11,000줄.

## 2. 파이프라인

```
KBO 일정(Schedule.asmx)  →  박스스코어(GetBoxScoreScroll)  →  문자중계 캐시(gzip)
                                                                    ↓
          득점가치(RE24) · 승리확률(WPA)  ←  투구 단위  ←  상태 기계  ←  타석 파싱

네이버 중계(relay?inning=N)  →  추적 캐시  →  구속 · 구종 · 릴리스 좌표
```

위 줄이 KBO 공식 기록, 아래 줄이 네이버 추적이다. **두 흐름은 섞이지 않는다.**

각 단계가 parquet 하나를 남기고 다음 단계는 그것만 읽는다.
원본 HTML/JSON은 gzip으로 보관하고 파싱은 캐시에서만 하므로,
파싱 규칙을 고칠 때 다시 수집하지 않는다.

### 부딪힌 문제들

- **엔드포인트 찾기** — KBO 기록실은 ASP.NET WebForms라 화면만 긁으면 막힌다.
  실제 데이터는 `.asmx` AJAX 엔드포인트가 JSON으로 내려준다.
- **필드 해독** — 박스스코어 `등판` 칸의 `7.8`은 "7회, 8번 타순부터".
  문서가 없어 문자중계와 대조해 알아냈다. 이 한 칸이 교체 타이밍 분석의 출발점이다.
- **역순 파싱** — 문자중계는 이닝 div 안이 역순이다. 되돌리지 않으면 주자·아웃 추적이 전부 어긋난다.
- **조용한 분류 오류** — 내야안타·번트안타를 안타로 세지 않아 1,065건을 놓쳤고,
  `"이중도루 실패시 2루까지 진루"`가 '실패'라는 글자 때문에 아웃으로 잡혔다.
- **정렬 버그** — RE24 평균이 0이어야 하는데 +0.029로 어긋났다.
  반이닝 중간에 투수가 바뀌면 투구수가 1로 리셋돼 시간 순서가 뒤섞이고 있었다.
  **검산이 없었으면 끝까지 몰랐을 버그다.**

## 5. 스스로 고친 것들

이 프로젝트의 리포트는 **수정 이력을 지우지 않는다.** 외부 평가를 두 차례 받아
아래를 고쳤고, 네 개 모두 내 수치를 깎았다.

| 지적 | 결과 |
|---|---|
| 불펜 등급을 **같은 시즌 성적**으로 정의 (타깃 누수) | 필승조 이득 78% 축소 |
| `(x0, z0)`는 릴리스가 아니라 **50피트 지점** 좌표 | 효과가 원래의 26%로 |
| 생존 편향 통제가 **반대 방향 편향**을 만듦 | +.025 → **+.018** |
| 자책점에 **승계 주자 실점**이 섞임 | 부진형 비중 −7.6%p |
| 실점이 아니라 **승리확률**로 재야 함 | 교체 이득이 유의하지 않아짐 |

## 6. 사전 등록

2026 시즌 종료(10월 9일) 전에 예측값을 고정했다.
`prereg.txt` · `prereg_designC.txt` · `prereg_manifest.json`

- 예측값은 **2017–2025만으로** 계산했다 (2026은 한 숫자도 쓰지 않음)
- 합격 기준: 9개 예측구간 중 **8개 이상**이 맞으면 재현
- 검정 방법도 고정: `python src/eda_runvalue_sweep.py --seasons 2026` (스크립트 수정 금지)

## 8. 데이터 정책

KBO 기록실과 네이버 스포츠 모두 **공개 문서가 있는 API가 아니다.**
수집은 개인 분석 목적으로 간격을 충분히 두고 했고,
**원시 데이터는 이 저장소에 포함하지 않으며 재배포하지 않는다.**
공개하는 것은 수집·파싱·분석 코드이며, 같은 데이터를 쓰려면 직접 수집해야 한다.
